# ERROR_CONTRACT.md

Todas las APIs deben usar este contrato. Prohibido exponer stack traces, SQL, secretos, tokens o errores tecnicos crudos.

## Forma

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Mensaje seguro para usuario.",
    "details": {}
  },
  "request_id": "req_..."
}
```

## Codigos internos de jobs

Estos codigos pueden guardarse en `job_runs.error_code` y logs internos seguros.
Solo pueden aparecer en endpoints admin/ops cuando el actor tenga permiso admin y
el mensaje sea seguro:

- JOB_LOCK_NOT_ACQUIRED
- JOB_RUN_ALREADY_ACTIVE
- ORDER_STATE_CHANGED_DURING_JOB
- CREDIT_RELEASE_FAILED
- NOTIFICATION_SEND_FAILED
- TELEGRAM_RATE_LIMITED
- AUTO_COMPLETE_BLOCKED_BY_DISPUTE
- JOB_CONFIG_INVALID

Mensajes seguros:

- `JOB_LOCK_NOT_ACQUIRED`: Otra ejecucion del job esta activa.
- `JOB_RUN_ALREADY_ACTIVE`: Ya existe una ejecucion activa.
- `ORDER_STATE_CHANGED_DURING_JOB`: El estado cambio durante el procesamiento.
- `CREDIT_RELEASE_FAILED`: No se pudo aplicar movimiento de creditos.
- `NOTIFICATION_SEND_FAILED`: No se pudo enviar la notificacion.
- `TELEGRAM_RATE_LIMITED`: El proveedor limito temporalmente los envios.
- `AUTO_COMPLETE_BLOCKED_BY_DISPUTE`: La orden no puede cerrarse porque hay disputa.
- `JOB_CONFIG_INVALID`: Configuracion de job invalida.
- `JOB_NOT_FOUND`: Job no encontrado.

## Codigos admin user/access control

- `USER_NOT_FOUND`: Usuario no encontrado o no visible.
- `USER_STATUS_INVALID`: Estado de usuario invalido.
- `USER_STATUS_TRANSITION_INVALID`: Transicion de usuario no permitida.
- `USER_STATUS_MUTATION_NOT_ALLOWED`: El actor no puede mutar ese usuario.
- `LAST_SUPER_ADMIN_REQUIRED`: Debe quedar al menos un `super_admin active`.
- `BUSINESS_ACCESS_LINK_NOT_FOUND`: Vinculo de acceso no encontrado o no visible.

## Mensajes

- Mensajes para usuario deben ser claros y cortos.
- Detalles tecnicos van a logs internos.
- Errores de permisos no deben revelar existencia de recursos ajenos.
- Errores de pago no deben prometer acreditacion si falta confirmacion.

## UI mapping

- 401: pedir reabrir Telegram Mini App o iniciar sesion.
- 403: mostrar accion no disponible.
- 404: mostrar recurso no encontrado.
- 409: refrescar estado de orden/anuncio.
- 422: marcar campo invalido.
- 429: mostrar espera.
- 5xx: mostrar error temporal y request_id.

## Observability errors - slice 24

- `OBSERVABILITY_DISABLED`
- `OBSERVABILITY_EVENT_INVALID`
- `OBSERVABILITY_EVENT_TOO_LARGE`
- `OBSERVABILITY_BATCH_TOO_LARGE`
- `OBSERVABILITY_RATE_LIMITED`
- `OBSERVABILITY_ACCESS_DENIED`
- `OBSERVABILITY_RETENTION_INVALID`
- `OBSERVABILITY_EXPORT_BLOCKED`

All critical error responses should include `request_id`. If `correlation_id` exists, it may be returned in a safe response/header. Stack traces, SQL, raw payloads, tokens, signed URLs, `storage_path`, `account_value` and full tx hashes are prohibited in user-visible errors.
