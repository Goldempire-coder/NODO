# API_CONTRACT.md

This slice uses the canonical order routes under `/api/v1`.

Authorized endpoints:

- `POST /api/v1/orders`
- `GET /api/v1/orders/{id}`
- `GET /api/v1/orders/mine`
- `POST /api/v1/orders/{id}/extend-payment-deadline`
- `POST /api/v1/orders/{id}/cancel`

Legacy `/orders` routes without `/api/v1` are prohibited.

## Common headers

Mutating endpoints require:

```txt
Authorization: Bearer <session_jwt>
Idempotency-Key: required
X-Request-Id: required or generated by backend
```

Read endpoints require:

```txt
Authorization: Bearer <session_jwt>
X-Request-Id: required or generated by backend
```

## POST /api/v1/orders

Request:

```json
{
  "ad_id": "uuid",
  "amount_usd": "50.00",
  "receiver_data": {
    "bank": "Banco",
    "phone": "+584121234567",
    "document": "V12345678",
    "holder": "Nombre Receptor"
  }
}
```

Response 201:

```json
{
  "data": {
    "order": {
      "id": "uuid",
      "public_order_code": "NODO-ABC123",
      "status": "waiting_payment",
      "amount_usd": "50.00",
      "rate_snapshot": "36.500000",
      "amount_bs_calculated": "1825.00",
      "business_name": "Casa Cambio Centro",
      "payment_method_snapshot": "zelle",
      "delivery_method_snapshot": "pago_movil_ve",
      "payment_instructions_masked": {},
      "payment_report_deadline_at": "timestamp",
      "extension_used": false,
      "expires_at": "timestamp"
    }
  },
  "request_id": "req_..."
}
```

Rules:

- Creates a persisted `waiting_payment` order.
- `created` is allowed only as audit/state event, not as final persisted status for this endpoint.
- Atomically validates ad/business/remitter, creates snapshot, moves ad `active -> in_order`, writes state event and audit.
- Does not consume credits, charge user, report payment, confirm business payment, deliver, chat or dispute.
- Must not reveal full payment instructions in response.
- Same idempotency key and same payload returns same order.
- Same idempotency key and different payload returns `IDEMPOTENCY_CONFLICT`.

## GET /api/v1/orders/{id}

Returns masked/summarized own order detail.

Rules:

- Remitter can read only own order in slice 04.
- Materializes expired `waiting_payment` order if read after deadline.
- Does not reveal full payment instructions.
- Does not expose `account_value`, storage paths, documents or internal ids beyond contract.

## GET /api/v1/orders/mine

Query:

```txt
status=waiting_payment|cancelled|null
cursor=opaque|null
limit=1..50
```

Response 200 includes:

```json
{
  "data": {
    "items": [],
    "next_cursor": "opaque|null"
  },
  "request_id": "req_..."
}
```

Rules:

- Cursor pagination.
- Own orders only.
- Masked/summarized orders only.
- No full payment instructions.

## POST /api/v1/orders/{id}/extend-payment-deadline

Request:

```json
{
  "reason": "Necesito unos minutos mas"
}
```

Rules:

- Own order only.
- Only `waiting_payment`.
- Only when `extension_used = false`.
- Adds 15 minutes once.
- Sets `extension_used = true`.
- Sets `payment_report_extension_used_at`.
- Writes state event and audit `payment_deadline_extended`.

## POST /api/v1/orders/{id}/cancel

Request:

```json
{
  "reason": "No pude realizar el pago"
}
```

Rules:

- Own order only.
- Only `waiting_payment` before payment report.
- Sets `status = cancelled`.
- Sets `cancel_reason = remitter_cancelled_before_payment`.
- If ad not expired, returns ad to `active`.
- If ad expired, materializes ad `expired`.
- Releases blocked ad credits according to credit contract.
- Writes state event and audit `order_cancelled`.
